Security

Your data stays on your infrastructure

InfraLedger is self-hosted by design. Applications, databases, logs and the audit log all live on servers you control, and nothing depends on a third-party cloud API.

Isolation

Enforced boundaries, not naming conventions

Organizations are the tenant boundary, and projects inside them get separate private networks. A workload in one project can't open a connection to another project's services.

Built-in controls

Security that's part of the platform

These controls apply to every organization and project. There's nothing to add on.

Tenant isolation

Each organization's resources are isolated from every other organization, and each project runs on its own private network.

Roles on every request

Owner, Admin and Member roles are enforced by the API on every call, not only hidden in the interface.

Audit log

Every deploy, restart, deletion, configuration change and admin action is recorded with the actor, time and outcome.

Encrypted secrets

Environment variables and service credentials are encrypted at rest.

Application firewall

IP allow-lists, basic auth and rate limits can be set for each application.

HTTPS by default

Every application gets a certificate from Let's Encrypt, renewed automatically.

Audit log

A complete record, stored where you choose

The audit log is kept in InfraLedger's own database on your servers. It records successful and failed actions, so you can answer who changed what, and when.

ETDLedger's security team can build threat detection on top of this record. See security services

Access

Who can reach your platform

Only people you invite. ETDLedger staff have no access to your installation unless you grant it, for example for a support request, and you can revoke it at any time.
