Product

A self-service platform on your own servers

InfraLedger turns raw servers into a self-service platform. Developers deploy, provision and operate from a dashboard, and you keep full control of the infrastructure.

Deploy

Push code, get a running service

Connect a Git repository or point at any container image. InfraLedger builds it, issues a certificate and runs it behind a load balancer.

  • Git deploys with Dockerfile detection or buildpacks
  • Deploy any image from a container registry
  • Automatic HTTPS for every app and custom domain
  • Replicas with health checks and sticky sessions
  • A disposable preview environment per branch
  • Deploy history with build logs and commit SHA
  • A console into running containers, no SSH needed
  • Scheduled and one-off jobs in the app's environment

Data services

Databases in a few clicks, isolated by default

Every data service runs on persistent storage inside its project's private network, with resource monitoring and scheduled backups.

  • PostgreSQL, MySQL and MariaDB with versioned engines
  • Redis for caching, with persistence options
  • S3-compatible object storage with access keys
  • RabbitMQ message queues
  • Scheduled backups with restore
  • Credentials and environment variables encrypted at rest

Networking

Routing, DNS and firewalls without config files

Set rules in the dashboard and InfraLedger compiles them into reverse-proxy configuration. Each project gets its own private network.

  • Path-based routing, redirects and rate limits
  • IP allow-lists and basic auth per application
  • DNS zone management for your own domains
  • Workloads can't reach other projects unless you connect them
  • One-click templates for common stacks

Observability

See what's running, and what changed

Metrics, logs and alerts sit next to the deploy history, so a spike lines up with the change that caused it.

  • CPU, memory, request and error rates per service
  • Centralized, searchable logs
  • Threshold alerts to Slack, email or any webhook
  • Usage dashboards per project and organization

In progress: staged configuration changes with a diff before applying, and one-click rollback with a preview of what will revert.

Access and audit

Multi-tenant from the first line of code

Organizations are fully isolated from each other, and every action is recorded.

Organizations and projects

Organizations are the tenant boundary. Projects group the apps, databases and services that belong together.

Roles enforced on every request

Owner, Admin and Member roles are checked by the API on every call, not just hidden in the interface.

Audit log

Every deploy, restart, deletion, configuration change and admin action, with who, when and the outcome.

Platform administration

A separate console to manage organizations, suspend abusive tenants and view system health.

Architecture

Docker on one server, Kubernetes on a cluster

A provider layer runs the same workloads on a single Docker host or a Kubernetes cluster, through the same dashboard and API. Moving from one to the other doesn't change how your developers work.
