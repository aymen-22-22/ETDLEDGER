ETDLedger / Security

Detection starts with a complete record.

ETDLedger stands for Enterprise Threat Detection Ledger. Every deploy, login, configuration change and network decision on InfraLedger becomes an entry with an actor, a time and an outcome. Our security team builds detection on that record, and on the systems around it.

§01The ledger approach

You can't detect what you didn't record.

Most incidents are found late because the evidence is scattered across tools. InfraLedger records the platform's activity in one place by design.

  1. 01

    Record

    Platform actions are written to the audit log with actor, timestamp and outcome.

  2. 02

    Enforce

    Roles and network boundaries are checked on every request, and denials are logged.

  3. 03

    Detect

    Rules and reviews run against the record to surface activity that doesn't fit.

  4. 04

    Respond

    Alerts go to the channels your team already uses, with the history attached.

§03Platform controls

Security controls built into InfraLedger.

These are part of the platform itself, not add-ons, so they apply to every organization and project.

Tenant isolation

Each organization's resources are isolated from every other, with private networks per project.

Role-based access

Owner, Admin and Member roles, enforced on every API call.

Audit log

Every deploy, restart, delete, config change and admin action, with actor, timestamp and outcome.

Encrypted secrets

Environment variables and service credentials encrypted at rest.

Application firewall

IP allow-lists, basic auth and rate limits per application.

Self-hosted by design

No third-party cloud API in the critical path. Your data stays on infrastructure you control.
