InfraLedger / Platform

The platform your team would build, already built.

InfraLedger turns raw servers, from a single Docker host to a Kubernetes cluster, into a self-service platform. Developers deploy, provision and operate from a dashboard, without Docker commands, YAML or SSH.

§01Deploy

Push code, get a running service.

Two ways in: connect a Git repository, or point at any container registry image. Every app comes out the other side with HTTPS, scaling and a deploy history.

Git-based deploys

Connect a repository. InfraLedger detects a Dockerfile, or falls back to buildpacks, then builds and deploys on push.

Image deploys

Point at any registry image and run it directly, with the same routing and scaling as Git deploys.

Automatic HTTPS

Every app gets a domain and a certificate through Traefik and Let's Encrypt, including app.localhost for local development.

Horizontal scaling

Run multiple replicas behind a built-in load balancer, with health checks and sticky sessions.

Environment variables

Encrypted at rest, with project-level shared secrets that apps can reference.

Preview environments

Every branch or pull request can get its own isolated, disposable deployment.

Deploy history

Each deployment is tracked with build logs, commit SHA and status.

Console and scheduled jobs

Open a shell in a running container from the browser, and run cron or one-off jobs in the app's environment.

§02Data services

§03Networking

Real tenant isolation, not a naming convention.

Routing, DNS and firewall rules are set in the dashboard and compiled into reverse-proxy configuration automatically.

Private networks per project

Workloads in one project cannot reach another project's services unless they're explicitly connected.

Custom routing rules

Path-based routing, redirects, rate limiting, IP allow-lists and basic auth, without hand-written proxy config.

DNS zone management

Manage DNS records for your own domains directly in the platform.

Template catalog

One-click starting points for common stacks, such as WordPress or a Node and Postgres starter.

§05Observability

See what's running, and what changed.

Metrics, logs and alerts sit next to the deploy history, so problems line up with the change that caused them.

Metrics

CPU, memory, request rate and error rate for every app and service, powered by Prometheus.

Centralized logs

Streamed, searchable logs for every application and service.

Alerting

Threshold-based alerts delivered to Slack, email or any webhook.

Usage dashboards

Per-project and per-organization views of what is consuming what.

Staged changes

Queue configuration changes and review a diff before applying them. In progress.

One-click rollback

Revert a deployment with a preview of exactly what will and won't revert: env vars, image, replicas. In progress.

§06Access & tenancy

Multi-tenant from the first line of code.

Organizations are the tenant boundary. Every organization's resources are fully isolated from every other, and every action is recorded.

Organizations and projects

Organizations hold projects; projects group the applications, databases and services that belong together.

Role-based access

Owner, Admin and Member roles, enforced on every API call rather than just hidden in the interface.

Audit log

Every deploy, restart, delete, config change and admin action, recorded with actor, timestamp and outcome.

Platform admin panel

A separate console to manage organizations, suspend abusive tenants and view system health.

Authentication

Email and password accounts with JWT-based sessions.

Engineering console UX

Dense, keyboard-navigable interface with a ⌘K command palette and light, dark and high-contrast themes.
